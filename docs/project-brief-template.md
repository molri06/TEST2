# 새 프로젝트 기획 프롬프트 템플릿

AI에게 "새 프로젝트를 만들어 달라"고 요청할 때 붙여 넣는 양식입니다.
대괄호 `[ ]` 안을 채우고, 필요 없는 항목은 지우세요. **★ 표시는 필수**입니다.

> 사용법: 아래 "복사용 템플릿"만 복사해서 채운 뒤 그대로 전달하면 됩니다.
> 작성 요령과 예시는 그 아래 "항목별 작성 가이드"에 있습니다.

---

## 1. 복사용 템플릿

```markdown
이 경로에 새 프로젝트를 만들려고 해. 아래 조건을 반영해 줘.

## 0. 한 줄 요약 ★
[누구]를 위한 [무엇]을 만든다. 왜냐하면 [이유].

## 1. 배경과 동기 ★
- 지금 겪는 불편/계기: [현재 어떤 방식으로 하고 있고 무엇이 불편한지]
- 이걸 만들면 달라지는 것: [기대하는 변화]
- 기존 대안을 안 쓰는 이유: [예: Notion은 무겁다 / Figma는 노트용이 아니다]

## 2. 정의 ★
- 형태: [웹 앱 / 모바일 앱 / 데스크톱 앱 / CLI / 라이브러리 / 플러그인 / 확장 프로그램]
- 한 문장 정의: [~하는 ~]
- 이 프로젝트가 **아닌 것**: [혼동되기 쉬운 인접 제품과의 선긋기]

## 3. 사용자와 사용 맥락 ★
- 주요 사용자: [나 혼자 / 팀 N명 / 불특정 다수]
- 사용 상황: [언제, 어디서, 어떤 기기로, 얼마나 자주]
- 사용자가 해결하려는 일(Job):
  1. [~할 때 ~하고 싶다]
  2. [ ]
- 성공 기준: [예: 아이디어 하나 적는 데 3초 이내 / 노트 200개에서도 끊김 없음]

## 4. 첫 버전(v1) 범위 ★
반드시 있어야 하는 기능 (없으면 제품이 성립하지 않는 것만):
1. [기능] — 사용자가 [이렇게] 하면 [이렇게] 된다
2. [ ]
3. [ ]

**v1에서 제외** (나중에):
- [ ]
- [ ]

## 5. 데이터와 상태
- 다루는 핵심 데이터: [예: 노트, 캔버스, 이미지, 태그]
- 저장 위치: [로컬(브라우저)/파일/서버 DB/미정 — 추천해 줘]
- 계정·로그인: [필요 없음 / 필요함 / 나중에]
- 여러 기기 동기화: [필요 / 불필요]

## 6. 스타일 키워드
- 무드: [예: Figma UI3 느낌으로 미니멀하게]
- 레퍼런스: [제품명 또는 이미지 첨부]
- 색/타이포 취향: [예: 무채색 기반 + 포인트 컬러 1개, 산세리프]
- 다크 모드: [필요 / 불필요 / 시스템 설정 따름]

## 7. 피하고 싶은 것
- 디자인: [예: 과한 그라데이션, 이모지 남용, 둥근 모서리 과다]
- 기술/구조: [예: 무거운 프레임워크, 불필요한 의존성, 과도한 추상화]
- 동작: [예: 팝업 튜토리얼, 자동 재생, 강제 로그인]

## 8. 기술 제약
- 선호 스택: [지정 / 없음 — 추천해 줘]
- 반드시 써야/쓰면 안 되는 것: [ ]
- 배포 방식: [로컬 실행 / 정적 호스팅 / 서버 / 스토어]
- 지원 대상: [브라우저·OS·화면 크기]

## 9. 산출물과 진행 방식 ★
- 이번에 받고 싶은 것: [기획서만 / 기획서 + 폴더 구조 / 동작하는 v1 코드]
- 진행 방식: [바로 구현해 줘 / 계획을 먼저 보여주고 확인받아 / 단계별로 나눠서]
- 확인 방법: [예: `npm run dev` 로 실행되게 / 테스트 포함 / README에 실행법 정리]
- 애매한 부분은: [알아서 정하고 가정을 적어 줘 / 나에게 물어봐]
```

## 2. 항목별 작성 가이드

| 항목 | 왜 필요한가 | 잘못된 예 → 좋은 예 |
|---|---|---|
| 0. 한 줄 요약 | 방향이 흔들릴 때 기준이 됨 | "노트 앱" → "혼자 쓰는, 무한 캔버스에 생각을 흩뿌려 두는 브레인스토밍 노트" |
| 1. 배경 | '왜'를 알면 기능 판단이 달라짐 | "필요해서" → "메모가 문서마다 흩어져서 연결이 안 보인다" |
| 2. 정의 | 형태에 따라 스택이 완전히 달라짐 | "앱" → "브라우저에서 도는 웹 앱, 설치 없이" |
| 3. 사용자 | 혼자 쓰면 로그인·권한이 통째로 빠짐 | "누구나" → "나 혼자, 노트북에서 작업 중 틈틈이" |
| 4. v1 범위 | 범위를 안 자르면 v1이 안 끝남 | 기능 12개 나열 → 핵심 3~5개 + 나머지는 제외 목록으로 |
| 5. 데이터 | 저장 방식은 나중에 바꾸기 가장 비쌈 | 생략 → "로컬 저장이면 충분, 동기화는 불필요" |
| 6. 스타일 | 키워드 3개면 톤이 잡힘 | "예쁘게" → "Figma UI3 느낌, 무채색 + 파랑 포인트 1개" |
| 7. 피할 것 | 금지 목록이 취향을 가장 빠르게 전달함 | 생략 → "그라데이션·이모지·팝업 금지" |
| 8. 기술 제약 | 취향이 없으면 "추천해 줘"라고 명시 | 공란 → "스택 지정 없음, 추천해 줘" |
| 9. 산출물 | 문서만 원하는지 코드까지인지 갈림 | 생략 → "기획서 먼저, 확인 후 구현" |

### 범위를 자르는 기준
각 기능에 대해 이렇게 물어보세요.
1. 이게 없으면 제품을 **한 번이라도 쓸 수 있나?** → 아니면 v1.
2. 없어도 쓸 수는 있나? → v2로.
3. "있으면 좋겠다"인가? → 백로그로.

## 3. 작성 예시 (참고용)

```markdown
## 0. 한 줄 요약
혼자 생각을 정리하는 사람을 위한, 무한 캔버스 기반 브레인스토밍 노트 웹 앱.
문서 단위 메모로는 아이디어 사이의 연결이 안 보이기 때문.

## 2. 정의
- 형태: 웹 앱 (설치 없이 브라우저에서)
- 한 문장: 무한 캔버스 위에 노트를 자유롭게 흩뿌리고 배치하는 도구
- 아닌 것: 협업 화이트보드(Miro)도, 문서 편집기(Notion)도 아님

## 3. 사용자와 사용 맥락
- 주요 사용자: 나 혼자
- 사용 상황: 노트북, 작업 중 아이디어가 떠오를 때 수시로
- Job: 떠오른 생각을 즉시 적고, 나중에 끌어다 묶고 싶다
- 성공 기준: 캔버스 열고 3초 안에 첫 글자 입력

## 4. v1 범위
1. 무한 캔버스 — 휠로 확대/축소, 드래그로 이동
2. 노트 생성/이동 — 빈 곳 더블클릭으로 생성, 드래그로 배치
3. 폰트 크기 조절 — 노트별로 크게/작게
4. 이미지 드래그 앤 드롭 — 파일을 캔버스에 떨구면 배치됨
5. 자동 저장 — 새로고침해도 유지

제외: 협업, 댓글, 노트 간 연결선, 검색, 태그, 내보내기

## 5. 데이터와 상태
- 핵심 데이터: 노트(텍스트/이미지), 위치, 크기
- 저장: 브라우저 로컬 저장으로 충분
- 로그인: 필요 없음 / 동기화: 불필요

## 6. 스타일
- Figma UI3 느낌의 미니멀. 무채색 + 포인트 컬러 1개, 산세리프
- 다크 모드: 시스템 설정 따름

## 7. 피하고 싶은 것
- 과한 그라데이션, 이모지 남용, 그림자 남발
- 캔버스를 가리는 상시 툴바, 팝업 튜토리얼
- 무거운 상태관리 라이브러리

## 9. 산출물
- 기획서 + 동작하는 v1 코드
- 계획을 먼저 보여주고 확인받은 뒤 구현
- `npm run dev` 로 바로 실행되게, README에 실행법 정리
- 애매한 부분은 알아서 정하고 가정을 적어 줄 것
```
